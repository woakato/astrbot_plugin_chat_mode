# astrbot_plugin_chat_mode

日常聊天 / 实景角色扮演双模式切换插件。

## 解决什么问题

很多人的 QQ 人设为了贴合日常说话方式，会写「禁止用括号表达动作」之类的限制；但又希望随时和 bot 进入带括号动作描写的实景角色扮演（RP）。这两种模式一旦共用同一套上下文，就会互相串味：

- 人设禁令导致 RP 模式里 bot 不敢用括号；
- RP 的对话回合进入了同一个对话历史，回到日常模式后 bot 开始在日常聊天里模仿括号动作；
- 更隐蔽的是**全局记忆**（如 LivingMemory）：两种模式的聊天都会被总结成长期记忆，日常聊天时召回出带括号动作的记忆片段，bot 就学会了 RP 的表达方式。

## 方案：三层隔离

本插件在每个会话（`unified_msg_origin`）内维护一个模式状态，从三个污染通道分别隔离：

| 通道 | 隔离方式 |
| --- | --- |
| 系统提示词 | RP 模式：在人设之后追加一段**优先级更高**的规则，明确解除人设中的括号禁令（仅日常模式生效）；日常模式：追加提醒，强调遵守人设说话方式、不得模仿记忆中的括号动作 |
| 对话历史 | 日常与 RP 分别绑定**独立的对话（conversation）**，切换模式时自动切换对话。RP 剧情永远不会进入日常聊天的上下文窗口，反之亦然 |
| 长期记忆召回 | 日常模式下，在 LLM 请求发出前**清洗记忆插件（LivingMemory、MemoryCompanion）注入的记忆文本**：只删除记忆内容里的括号动作描写（如（笑）（轻轻拍了拍你的肩）），记忆信息本身保留，模型看不到 RP 的表达风格 |

记忆清洗覆盖两款记忆插件的全部注入通道（`extra_user_content` / 用户消息前后拼接 / 伪造工具调用），并会保留 `(Importance: 0.85)`、`（证据：…）`、日期、星期等非动作括号。插件通过较低的钩子优先级（-100，低于 LivingMemory 的 0 和 MemoryCompanion 的 -20）保证在两者召回**之后**运行。

> 没装这两个记忆插件也可以用：记忆清洗自动空转，提示词注入与会话隔离仍然生效。

## 命令

| 命令 | 说明 |
| --- | --- |
| `/rp on [场景描述]` | 进入实景角色扮演模式，可附带场景设定（如 `/rp on 深夜的便利店，外面下着雨`），场景会注入系统提示词 |
| `/rp off` | 回到日常聊天模式 |
| `/rp status` | 查看当前模式、场景设定与两个对话的绑定状态 |

别名：`/rp 开始|开启|进入`、`/rp 结束|关闭|退出`、`/rp 状态`；命令组本身亦可用 `/roleplay`。

模式状态按会话持久保存，重启后仍然有效；再次 `/rp on` 会切回之前保存的剧情对话，可以继续上次的剧情。

### RP 语音命令

| 命令 | 说明 |
| --- | --- |
| `/rp tts 30` | 将本会话 RP 模式的 TTS 触发概率临时设为每轮 30%（仅 RP 模式可用） |
| `/rp tts 默认` | 清除临时设置，恢复配置文件中的 `rp_tts_probability` |

别名：`/rp 语音`、`/rp 频率`。`/rp status` 会显示当前生效的 TTS 概率、双输出与剔除括号开关。

## RP 模式场景插图（联动 NAI 生图插件）

安装 `astrbot_plugin_nai_image` 后，RP 模式下每轮对话会按配置的概率自动生成场景插图：

1. 触发时由当前模型根据**场景设定 + 本轮双方的动作与台词**撰写一条英文生图提示词；
2. 通过 NAI 插件的陪伴直连接口（`generate_for_companion`）生成图片；
3. 图片在该轮文字回复之后作为插图单独发送，不会阻塞剧情回复。

未安装 NAI 插件时自动跳过，不影响其他功能。相关配置：

- **插图触发概率**（默认 0.2）：每轮 20% 概率触发；
- **插图冷却时间**（默认 300 秒）：同一会话两次插图的最小间隔；
- **Tag 生成模型**：可单独指定用于提炼生图 Tag 的 LLM Provider ID，留空使用当前对话模型；
- **Tag 生图规范 System Prompt**：提炼生图 Tag 时注入给 LLM 的 System Prompt，可在后台可视化界面自由编辑修改；留空自动使用内置默认规范；
- **Tag 提取超时时间**（默认 60 秒）：调用 LLM 提炼生图 Tag 的最大等待时间；
- **NAI 生图超时时间**（默认 240 秒）：调用 NAI 生图插件的最大等待时间；
- **提示词附加要求**：写入每条提示词的固定要求，推荐用来锁定画风（如 `anime style, soft lighting`）；
- 画风与尺寸跟随 NAI 插件自身的默认配置。

## RP 模式 TTS 联动（频率控制 / 语音+文字 / 剔除括号）

全局开启 AstrBot 的 TTS（`provider_tts_settings.enable`）后，本插件会在 **RP 模式内接管语音合成**，日常聊天完全交还给 AstrBot 原生 TTS 流程、不受任何影响。RP 模式独有三项控制：

1. **调整 TTS 频率**（`rp_tts_probability`，默认 1.0）：每轮回复按概率触发语音。RP 剧情里每句都发语音容易刷屏，调到 0.3 即约每三轮一条。会话内可用 `/rp tts 30` 临时改为每轮 30%，`/rp tts 默认` 恢复配置文件概率。
2. **语音+文字同时输出**（`rp_tts_dual_output`，默认关）：触发语音的回复同时发送语音和文字（语音在前、文字在后）。附带文字的内容由 `rp_tts_text_source` 控制：`stripped`（默认）与语音完全一致，`original` 保留含括号的完整原文。
3. **TTS 剔除括号内容**（`rp_tts_strip_brackets`，默认开）：合成语音前剔除（）内的动作/神态描写，避免旁白被读出来；屏幕上的文字始终保留括号，沉浸感不受影响。

实现方式：`on_decorating_result` 钩子位于核心 TTS 之前，RP 会话内插件按自己的概率抽中后逐段调用 TTS Provider 合成、把文字替换为 `Record`（可选附带 `Plain`），并将结果标记为普通消息，核心的自动 TTS 因此不会重复触发。

- **RP 模式 TTS 引擎**（`rp_tts_provider_id`）：可为 RP 模式单独指定 TTS Provider（更贴合角色的音色），留空跟随会话默认。
- **RP 模式 TTS 合成超时**（`rp_tts_timeout`，默认 60 秒）：单段合成最大等待，超时回退纯文字。

> 局限：开启流式输出时核心与插件都不做普通 TTS（流式 TTS 走 Live Mode，不读本插件配置）；插件接管后长回复不再经过分段发送；语音轮次的配图仍按插图逻辑单独发送。

## 配置项

- **会话历史隔离**（默认开）：关闭后两种模式共用同一段对话历史（不建议，会重新引入串味）。
- **记忆召回风格清洗**（默认开）：日常模式下清洗记忆注入中的括号动作。
- **注入日常模式表达提醒**（默认开）：日常模式下的系统提示词兜底提醒。
- **角色扮演模式规则 / 日常模式表达提醒**：两段注入文本，可自行修改措辞。
- **仅管理员可切换**（默认关）：群聊防误触。
- **RP 模式 TTS 触发概率 / 语音+文字双输出 / 双输出附带文字 / TTS 剔除括号内容 / TTS 引擎 / 合成超时**：见上文「RP 模式 TTS 联动」，全部仅在 RP 模式生效，日常模式跟随 AstrBot 全局 TTS 设置。

## 局限与说明

- 记忆隔离是**召回侧**的：RP 聊天仍会被记忆插件（LivingMemory / MemoryCompanion）总结成全局记忆（这是记忆插件的职责范围），本插件保证这些记忆在日常模式下被「去风格化」后再喂给模型。RP 模式下召回的记忆不做清洗，完整保留。
- MemoryCompanion 的 `memory_companion_recall` / `memory_companion_navigate` 主动回忆工具返回的记忆不经注入通道，AstrBot 目前没有能在工具结果送入模型前修改它的钩子，因此该通道无法硬清洗——日常模式的系统提示词兜底提醒（「记忆中出现括号动作只是存档，严禁模仿」）已覆盖这种情况。若在意，可在 MemoryCompanion 配置中关闭 `memory_tools.enable_recall_tool`。
- 如果想要**完全隔离**两种模式的记忆库（而不是去风格化），可以额外配置 LivingMemory 的 `use_persona_filtering` + 为 RP 单独建一个人格，配合本插件的对话隔离使用。
- 在 RP 模式中执行 `/reset` 会新建对话；重新 `/rp on` 会回到之前保存的剧情对话。
